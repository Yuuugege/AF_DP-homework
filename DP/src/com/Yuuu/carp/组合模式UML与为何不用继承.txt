6 组合聚合复用原则作业（资料题）答案

作业1：组合模式（Composite Pattern）及其 UML 描述

1. 定义
组合模式是一种结构型设计模式，它将对象组合成树形结构以表示"部分-整体"的层次结构，
使得客户端对单个对象（叶子节点）和组合对象（容器节点）的使用具有一致性。

2. UML 结构组成
组合模式的 UML 图由以下角色构成：
（1）Component（抽象构件）：定义叶子构件和容器构件的公共接口，声明叶子与容器共有的
操作（如 add、remove、getChild、operation 等）。
（2）Leaf（叶子构件）：叶子节点对象，是树形结构中最末端的对象，没有子节点，实现
Component 中声明的叶子相关操作。
（3）Composite（容器构件）：容器节点对象，包含子节点（叶子或容器），实现管理子节点的
操作（add、remove、getChild 等），并在 operation 方法中递归调用其所有子节点的 operation
方法。
（4）Client（客户端）：通过 Component 接口操作整个组合结构，无需区分叶子节点与容器节点。

3. UML 关系
Component 是 Leaf 和 Composite 的公共抽象（父类或接口）；Composite 与 Component 之间是
聚合关系，即一个 Composite 可以包含多个 Component 子对象，从而形成树形结构。

作业2：为何不用继承？

本案例中，心脏（Heart）、学生（Student）、教师（Teacher）、班级（Class）、学校（School）
之间的关系，都应当用组合/聚合/关联来表达，而不使用继承，其根本原因正是"组合聚合复用
原则"（Composite/Aggregate Reuse Principle，CARP）：在进行复用时，应优先使用组合/聚合
等关联关系，其次才考虑继承关系。具体原因如下：

1. 继承表达的是"是一个（is-a）"关系，而本案例中的关系本质上是"有一个（has-a）"关系。
例如：学生"有一个"心脏、班级"有多个"学生、学校"有多个"学生，这些都不是"学生是一种
心脏"或"班级是一种学生"的 is-a 关系，因此使用继承在语义上不成立。

2. 继承是"白盒复用"：父类的内部实现细节对子类可见，会破坏封装性；而组合/聚合是"黑盒
复用"：对象通过引用其他对象来复用其功能，只依赖其公开接口，不暴露内部实现。

3. 继承是静态的，在编译期就已确定，运行时不能改变继承关系；而组合/聚合是动态的，在
运行时可以灵活地替换、增减被组合的对象。

4. 继承会导致强耦合：存在"脆弱的基类"问题，父类一旦修改，所有子类都可能受到影响；
而组合/聚合通过接口隔离依赖，耦合度更低。

5. Java 只支持单继承：一个类只能继承一个父类，但可以通过组合/聚合同时复用多个对象的
能力，灵活性更高。

具体到本案例的三种关系：
（1）组合关系（心脏与 Student/Teacher）：人和心脏是共生关系，人不存在了心脏自然没有存在
的机会，心脏的生命周期完全依附于人，适合用组合来表达——在 Student/Teacher 类内部创建
Heart 对象，使其随人的创建而创建、销毁而销毁。
（2）聚合关系（Student 与 Class/School）：班级和学校包含学生，但彼此可以单独存在，适合用
聚合来表达——在 Class/School 类中使用 List<Student> 声明成员属性。
（3）关联关系（Teacher 与 Student）：教师与学生只是引用关系，彼此之间不存在"整体-部分"
的包含关系，适合用关联来表达——在类中使用 List 声明成员属性进行引用。

因此，本案例应当使用组合、聚合、关联关系来实现复用，而不是继承。
